# Vexo 官方手势模板流程与实机验证边界

核查日期：2026-11-14。本地官方源码固定于 `1e4291e2fa4896b1f603d3d4f0b009c483425da0`；本轮已核对 remote main 的识别器与本地一致。Python 移植位于 `gesture_matcher.py`，沿用原项目 MIT 许可。

## 原理与旧规则的区别

官方流程是每个动作录制三次，以 50 Hz 的加速度、角速度六轴数据建立模板，再比较新动作与最近模板的距离。当前应用分别学习举起、放下各三次；不再以“相对起始姿态超过固定 130°”作为识别依据，但保留从下垂姿态起步、快动作和放下后重新待命等应用条件。训练时的动作方向、佩戴方式和姿态都会影响模板。[官方使用说明](https://github.com/VexoAI-Org/vexo-open-kit/blob/1e4291e2fa4896b1f603d3d4f0b009c483425da0/projects/gesture-trainer/README.md)

1. **分段**：角速度模长超过 40°/s，或相邻加速度变化超过 0.08 g，视为运动。连续安静 300 ms 后结束，只接受 200–3000 ms 的运动段。
2. **形成模板**：按设备时间线性插值为 24 个点；每点包含六轴，角速度除以 250，得到 144 个数。
3. **匹配**：计算对应六维点的平均欧氏距离，选择最近的已录制示例。默认距离大于 0.5 返回未知；距离不是概率或置信度。

这里的“形状”是传感器随时间变化的序列，包括重力分量；没有恢复世界坐标中的三维手部轨迹、绝对位置或举手高度。[官方识别器](https://github.com/VexoAI-Org/vexo-open-kit/blob/1e4291e2fa4896b1f603d3d4f0b009c483425da0/projects/gesture-trainer/recogniser.js)

## 真实 50 Hz 流的限制

- **停顿决定边界**：举起后若未保持至少 300 ms 的安静就放下，up/down 可能合成一个动作；微小运动超过阈值也会延后结束。训练与使用应保持相同的“静止 → 举起 → 静止”节奏。超过 3 秒的运动会被拒绝。
- **末尾会裁剪**：300 ms 安静用于确认结束，但模板只保留到最后一个被判定为运动的样本，确认所用的静止尾部不进入形状。因此识别至少要等待这段确认时间，不能在手刚到位时立即输出；起始静止也不进入模板。
- **时间归一化不等于速度无关**：24 点重采样消除了整体时长差异，角速度仅除以固定 250，没有按幅度归一化。同一物理动作做得更快，角速度通常更大，匹配距离仍可能增加；含重力的加速度也使换手、表带旋转和起始姿态影响结果。
- **序号回绕：独立模块与应用不同**：官方 SDK 输出 uint32 序号。独立 `gesture_matcher.py` 额外要求相邻 `n` 相差 1，未取模，`4294967295 → 0` 会误判断流；50 Hz 不重启采样约 994 天才到此边界。实际应用的 `trained_raise.py` 已自行按 uint32 验证连续性，并向分段器传入 `n=None`，因此避免了这项误判；真正丢包和重新开流仍会切断旧动作。[协议](https://github.com/VexoAI-Org/vexo-open-kit/blob/1e4291e2fa4896b1f603d3d4f0b009c483425da0/contract/contract.md)、[Python SDK](https://github.com/VexoAI-Org/vexo-open-kit/blob/1e4291e2fa4896b1f603d3d4f0b009c483425da0/python/vexo_open/band.py)

## 已验证与待验收

官方明确说明：这些阈值是为模拟动作设定的猜测，尚未在真人手腕上验证；已测的是一只静放桌面的手环。不能把官方 demo 当作已有真人识别率保证。[官方说明](https://github.com/VexoAI-Org/vexo-open-kit/blob/1e4291e2fa4896b1f603d3d4f0b009c483425da0/projects/gesture-trainer/README.md)

本次 Python 移植已通过官方 Node.js 识别器的 Circle、Shake、Flick 合成输入差分测试，分段一致、形状与距离在浮点误差范围内一致。这证明移植符合官方算法，不证明真人动作效果；合成测试仅拉伸时间而保持角速度幅度，也不能证明真实速度变化下的鲁棒性。

建议录完各三次训练样本后，另做 **五次新的实机举手动作**，逐次对照预期与收到的事件，记录漏识别和重复触发。再做正常手势负样本，例如打字、转腕、挠头、抬到肩部、放下手臂，观察是否误报，并尝试稍快、稍慢的动作。训练样本、历史轨迹回放和这轮新实测须分别报告；五次验收也只说明当前佩戴方式下的演示表现，不能代表普适识别率。

## 现场验收摘要

62 号在当前佩戴方式下通过 BLE 录齐三次举起、三次放下。训练期间没有产生 `hand_raise`，离线回放得到的模型与实时保存模型一致。个人动作参数、原始诊断与模型保留在被 Git 忽略的本地 `runtime/`，不随源码发布。

模型录好后，另做五次新的快速上举，Mac 恰好收到五个事件；头顶保持没有重复，放下没有额外事件。首次普通动作检查未恢复待触发状态，因此没有作为有效误报证明；随后从已准备状态执行肩高动作，判为未知且无事件。这些只支持当前佩戴方式下的演示表现，不能代表普适识别率。

77 号复用模型尚未通过严格事件验收。新的 `SustainedPoseEstimator` 独立保存每只手环的下垂/头顶方向，不依赖完整动作分段；双人 MATCH 已完成一轮真实举起与放下的联动验收。它是姿态代理，不是手部高度测量，大幅转腕仍可能失去匹配。

软件覆盖包括与官方 JavaScript 合成输入对齐、训练期间不输出事件、模型持久化、锁存/重新待命、录制→回放一致性、持续姿态与现有心率/灯光回归。
