## 1. 目标

让一个评委拿起手机，**不需要讲解**，就能完成：填资料 → 看到为什么值得聊 → 用摄像头找到人 → 碰一下确认 → 听到开场白。

整条体验要能在**没有后端、没有震动、没有碰撞检测**的情况下照样走完（用假数据和后备按钮）。

## 2. 不在范围内

- 手环蓝牙、LED、Deepgram、Gemini、ElevenLabs（Will 负责）
- 账号、登录、持久化存储
- 人脸识别（只识别二维码标记）

## 3. 页面与需求

### Screen A — 加入（Join）

| 字段 | 必填 | 说明 |
|---|---|---|
| 名字 | 是 | |
| LinkedIn / 网站 | 否 | 只显示，不抓取 |
| 我正在做 | 是 | 一行 |
| 我想找能帮我…的人 | 是 | 一行 |
| 我能提供 | 是 | 一行 |
| 同意参与配对 | 是 | 勾选框，不勾不能提交 |

- 按钮：**FIND MY PEOPLE** → 发送 `guest_join`
- 提交后显示"正在寻找…"的等待动画，等后端推送 `match_found` 或 `no_match`
- **验收：** 漏填必填项时按钮不可点；提交后 1 秒内出现等待动画

### Screen B — 配对结果（Match）

- 标题：**Someone here can help with {headline}**
- 正文：`reason`（"你缺什么 → 他有什么"）
- 小字：依据 `evidence`，可以折叠
- 按钮：**FIND THEM** → 发送 `find_start`；**Maybe later** → 发送 `match_dismiss`
- 有震动的设备震一下（`navigator.vibrate`）；没有震动的设备用脉冲动画代替
- **验收：** 理由文字完整显示、不截断；在 iPhone 上（没有震动）也有明显的视觉提示

### Screen C — 找人（Find）

- 打开后置摄像头（`getUserMedia`，`facingMode: environment`）
- 用 **jsQR** 在本地逐帧识别 Wingman 二维码，不依赖网络
- 三种状态：

| 状态 | 画面 | 发送事件 |
|---|---|---|
| 扫描中 | 平静的扫描动画 | — |
| 锁定 | 目标光圈套住二维码 + 强震动 | `target_locked` |
| 丢失 | 回到扫描动画 | `target_lost` |

- 底部常驻按钮：**我已经找到了**（摄像头不可用时的后备）
- 摄像头权限被拒 → 显示说明和"我已经找到了"按钮，不卡死
- **验收：** 在比赛场地的灯光下，3 米内能识别打印的二维码

### Screen D — 交换名片（Handshake）

- 提示："用手机轻碰对方的手环"
- 用 `DeviceMotionEvent` 检测加速度峰值（阈值先定 2.5g，现场再调），检测到后发送 `phone_bump`
- iOS 需要先点按钮请求运动权限（`DeviceMotionEvent.requestPermission()`）
- 后备按钮：**确认见面** → 发送 `confirm_fallback`
- 收到 `state_changed: meeting_confirmed` → 绿色光圈 + 成功动画 + 对方的**项目卡片**（不放大头照）
- 收到 `whisper_ready` → 显示 **▶ 听开场白**，点击播放 `audio_url`（浏览器要求用户手势才能播放音频）
- **验收：** 没有运动传感器也能用后备按钮走完；音频能在 iPhone Safari 上播放

### Screen E — 记一笔（Follow-up）

- 输入框："你们聊了什么？"
- **起草跟进消息** → 发送 `note_submit`，显示返回的 `followup_draft`，可以编辑、复制
- 不会自动发送任何东西
- **验收：** 草稿可以编辑、一键复制

### 全局

- 所有页面都由 `state_changed` 驱动；断线后自动重连，并显示"重新连接中"
- 收到 `error` 时，如果 `retry: true` 显示重试按钮
- 首页右上角有"暂停配对 / 退出"

## 4. 视觉与措辞

- 深色背景，克制的渐变，圆形动效
- **紫色 = 发现，绿色 = 成功**，和手环 LED 一致
- 风格偏编辑感、高级感，不要做成社交 dashboard 或聊天机器人
- 措辞以工作和项目为中心，**避免约会感**：不用 "your person"、"spark"、"hunt"，用 Find、Handshake、"here's why you two should talk"

## 5. 实物

- 打印 2 份 Wingman 二维码标记（A6 大小，加粗边框，方便识别），戴手环的人别在胸前
- 二维码内容：`wingman:demo`

## 6. Demo（3 分钟）

| 时间 | 内容 | 谁操作 |
|---|---|---|
| 0:00–0:30 | 问题：满屋子人，不知道该找谁 | Holly 讲 |
| 0:30–1:00 | 戴手环的人对着手环说出需求 | 戴手环的人 |
| 1:00–1:30 | 嘉宾在手机上填资料 → 手环闪紫 → 手机显示理由 | 嘉宾 |
| 1:30–2:10 | 嘉宾打开摄像头找到标记 | 嘉宾 |
| 2:10–2:40 | 手机碰手环 → 变绿 → 播放开场白 | 嘉宾 |
| 2:40–3:00 | 收尾："LinkedIn 告诉你他是谁，Wingman 告诉你为什么该聊" | Holly 讲 |

- **讲 demo 时，嘉宾要带着一个具体问题入场**（比如"我在找懂硬件的 co-founder"），不要讲成一个人去找另一个人
- 准备一份录屏备用，现场网络或硬件出问题时播放

## 8. 完成标准

一位没看过产品的评委，用自己的手机扫码进入，在不需要讲解的情况下完成整个流程，并且能说出"为什么系统让我去找这个人"。
